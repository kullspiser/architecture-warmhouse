# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могу управлять отоплением 
- Система поддерживает управление отоплением посредством общего хаба "Умный дом"
- Пользователь не может самостоятельно подключить датчик управления отоплением

**Мониторинг температуры:**

- Пользователи могут проверять температуру
- Система поддерживает посредством общего хаба "Умный дом"
- Пользовать не может самостоятельно подключить датчик мониторинга температуры


### 2. Анализ архитектуры монолитного приложения

- Основной язык разработки: Go
- База данных: PostgreSQL
- Синхронное взаимодействие, никаких асинхронных запросов и реактивности
- Не возможности для пользователя взаимодействовать с системой для проведения собственных интеграций

### 3. Определение доменов и границы контекстов

- Домен "Управления отоплением" - работа с датчиками отопления
- Домен "Мониторинг температуры" - работа с датчиками температуры
- Домен "Панель пользователя" - центральная часть, доступная пользователю как интерфейс где он управляет отоплением и мониторит температуру
- Домен "Административная часть" - часть системы, доступная только сотрудникам компании, где происходит подключение новых пользователей и их датчиков

### **4. Проблемы монолитного решения**

- Нет возможности пользователю подключить свои устройства, а также текущие устройства подключаются
  только с помощью сотрудников компании - монолит не может позволить быстро и адаптивно добавить этот функционал,
  потому что возникнут проблемы с масштабированием и стабильностью всей системы.
- Монолит не позволяет быстро проводить масштабирование, допустим при подключении большого количества новых клиентов
  или резкого всплеска трафика
- Нет возможности проводить релиз распределено - т.е. для обновления модуля управления температурой
  нужно обновлять все приложение, что теоретически не безопасно и может сделать приложение в целом недоступным
- Т.к. решение является монолитом то интеграция новых функций затруднена - нужно тестировать все приложение и
  и команде нужно знать как приложение работает в целом, что несет риск появления новых багов
- Нет возможности расширения ответственности отдельных команд - т.к. приложение монолит то разделение команды разработки
  на более мелкие команды затруднено т.к. будет теряться контекст разработки и изменения одной команды будет аффектить на изменения
  другой команды
- Постоянно растущих технический долг, т.к. нет возможности вывод из эксплуатации ненужных модулей или обновления 
  зависимостей без сильного влияния на всю систему

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors

Должно при каждом вызове отображаться разное значение температуры

Ревьюер будет проверять точно так же.
